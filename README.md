## 🎯 프로젝트 개요

세금법률 챗봇 서비스는 **청년 사용자를 위한 맞춤형 세금 및 법률 정보 제공 챗봇**입니다.

복잡한 세금 용어와 법률 정보를 쉽고 빠르게 찾을 수 있도록 돕는 AI 기반 대화형 서비스입니다.

## 🔍 프로젝트 배경

### 문제 인식

- 청년 사용자들이 세금 관련 정보를 찾기 어려움
- 공공 문서 접근성 및 통합 데이터베이스 부재
- 복잡한 법률 용어로 인한 이해도 저하

### 해결 방안

AI 기반 대화형 챗봇을 통해 복잡한 세금·법률 정보를 쉬운 언어로 제공하고, 사용자의 질문 맥락을 이해하여 정확한 답변을 제공합니다.

## 🛠 기술 스택

### Backend
- **Language**: Java 21, Python 3
- **Framework**: Spring Boot 3.x, FastAPI
- **Database**: Oracle 23ai, Redis
- **AI/ML**: LangChain, LangGraph

### Frontend
- **Framework**: React.js

### 캐싱 & 최적화
- **Cache**: Redis (대화 히스토리 관리)

---

## ✨ 주요 기능

### 1. 세금 관련 질의응답
다양한 세금 관련 질문에 대한 정확한 법률 기반 답변 제공

### 2. 법률 정보 검색
복잡한 법률 용어를 쉬운 언어로 설명

### 3. 대화 히스토리 관리
Redis 캐싱을 활용하여 이전 대화 맥락을 유지하고 연속적인 상담 가능

### 4. 하이브리드 검색
BM25(키워드 기반) + Vector(의미 기반) 검색을 결합하여 검색 정확도 향상

### 최적화 단계

#### 1단계: 쿼리 재작성 노드 개선
**개선 내용**
- 초기 시스템에서 쿼리 재작성 프로세스 제거
- 불필요한 처리 단계 축소로 응답 속도 개선

**효과**
- 전체 처리 시간 단축

---

#### 2단계: 검색(Retrieve) 노드 최적화
**개선 내용**
- **하이브리드 검색 도입**: BM25 + Vector 검색 결합
- 키워드 기반 검색과 의미 기반 검색의 장점 결합

**효과**
- 검색 정확도 향상
- 다양한 질문 유형에 대한 대응력 강화

---

#### 3단계: 대화 히스토리 관리

**문제점**
- 매 요청마다 LLM에 전체 대화 히스토리 전송
- 과도한 연산 및 느린 응답 속도
- 메모리 과다 사용

**해결책**
- **Redis를 활용한 대화 히스토리 캐싱**
  - 첫 번째 질문: Oracle DB 조회 후 Redis 저장
  - 2~9번째 질문: Redis에서 빠르게 조회
  - 10번째 질문: 이전 질문/답변 제거 후 최신 대화만 유지
  - 요약문 생성 및 저장으로 메모리 최적화

**최적화 플로우**
```
채팅방 클릭
    ↓
DB에서 최근 대화 이력 조회 → Redis에 저장
    ↓
대화 진행 (1~9번째)
    ↓
10번째 대화 도달
    ↓
이전 대화 요약 생성 → 오래된 대화 제거 → 요약본 + 최신 대화만 유지
    ↓
Redis 업데이트 → DB 동기화
```

**효과**
- 응답 속도 대폭 개선
- 메모리 사용량 최적화
- 대화 맥락 유지하면서도 효율적인 처리
